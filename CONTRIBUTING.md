# Contributing to NewSocOps

Thank you for your interest in contributing to NewSocOps! This document provides guidelines for participating in our community.

## Code of Conduct

By participating in this project, you agree to abide by our [Code of Conduct](CODE_OF_CONDUCT.md). Please read it before contributing.

## Ways to Contribute

There are many ways to contribute to NewSocOps:

### 1. Apply for a Grant

If you're working on an open-source project that needs support:
- Review our [grants process](docs/grants-process.md)
- Use our [grant application template](.github/ISSUE_TEMPLATE/grant-application.yml)
- Submit a detailed proposal

### 2. Review Grant Applications

Help evaluate grant applications:
- Read applications labeled `grant-candidate`
- Provide constructive feedback
- Share relevant expertise
- Ask clarifying questions

### 3. Improve Documentation

Help make our documentation better:
- Fix typos or unclear explanations
- Add examples or clarifications
- Translate documentation to other languages
- Update outdated information

### 4. Share Your Experience

- Write about your grant-funded project
- Share lessons learned
- Create case studies
- Contribute to our blog (if available)

### 5. Spread the Word

- Share NewSocOps with relevant projects
- Mention us in your project if we funded it
- Help grow the community

## Contribution Process

### For Documentation Changes

1. **Fork the repository**
   ```bash
   git clone https://github.com/NewSocOps/community.git
   cd community
   ```

2. **Create a branch**
   ```bash
   git checkout -b improve-documentation
   ```

3. **Make your changes**
   - Edit relevant markdown files
   - Follow our style guide (see below)
   - Test any links

4. **Commit your changes**
   ```bash
   git add .
   git commit -m "docs: improve grants process clarity"
   ```

5. **Submit a pull request**
   - Describe your changes clearly
   - Reference any related issues
   - Be responsive to feedback

### For Grant-Related Feedback

1. Navigate to the grant application issue
2. Read the full proposal
3. Provide constructive, specific feedback
4. Be respectful and professional
5. Focus on helping improve the application

## Style Guide

### Markdown Formatting

- Use ATX-style headers (`#` not underlines)
- Use `-` for unordered lists
- Use `1.` for ordered lists
- Include blank lines around headers and lists
- Use code blocks with language specification

### Writing Style

- Be clear and concise
- Use active voice
- Avoid jargon when possible
- Define terms when necessary
- Use inclusive language
- Provide examples when helpful

### Commit Messages

Follow the Conventional Commits specification:

- `docs:` for documentation changes
- `feat:` for new features
- `fix:` for bug fixes
- `chore:` for maintenance tasks

Examples:
```
docs: add grant eligibility criteria
feat: add grant application template
fix: correct broken link in README
chore: update monthly report template
```

## Review Process

### Pull Request Reviews

All contributions are reviewed by maintainers:

1. **Initial Review** (1-3 days): Basic checks and feedback
2. **Discussion**: Address any questions or concerns
3. **Approval**: Maintainer approval required
4. **Merge**: Changes are merged into main branch

### Grant Application Reviews

Grant applications follow a different process outlined in [grants-process.md](docs/grants-process.md).

## Communication Channels

- **Issues**: For bug reports, suggestions, and discussions
- **Pull Requests**: For proposing specific changes
- **Discussions**: For general questions and community conversation

## Recognition

Contributors are recognized in the following ways:

- Listed in relevant documentation or reports
- Mentioned in monthly reports (for significant contributions)
- Acknowledged in project communications

## Questions?

If you have questions about contributing:

1. Check existing [issues](https://github.com/NewSocOps/community/issues)
2. Review our [documentation](docs/)
3. Open a new issue with the `question` label
4. Reach out via community channels

## Getting Help

Need help getting started?

- Look for issues labeled `good first issue`
- Ask questions in issue comments
- Review previous pull requests for examples
- Reach out to maintainers
